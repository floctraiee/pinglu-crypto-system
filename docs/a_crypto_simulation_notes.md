# 设备模拟与密码模块说明

## 密码原理

系统为每台模拟设备配置独立的 SM2 密钥对，私钥保留在设备端，
公钥预先登记到网关和中心。感知记录采用统一 JSON 规范化编码，
使用 SM3 计算包含设备身份、时间、位置、序号、业务数据及前序摘要
的记录摘要，形成每设备独立、跨批次连续的摘要链。

默认每10条记录组成一个批次，以记录摘要构建 Merkle 树，并使用
设备 SM2 私钥对包含设备ID、批次号、序号范围、数量、时间范围及
Merkle根的批次头进行签名。网关和中心使用预登记公钥及相同编码
规则独立验证。该机制用于发现签名后的数据篡改，不能判断设备在
签名前生成的业务数值是否真实。

## 模拟数据说明

系统模拟水位、气象、航标、边坡、船闸、无人机和测量船七类
感知数据，所有数据均为程序生成，不属于真实运河实测数据。
不同类型使用对应的业务字段，测量值和经纬度采用十进制字符串，
时间带 +08:00 时区。

模拟器支持设备数量、生成频率、批次大小和随机种子配置。
批次及设备续接状态保存到本地 SQLite 数据库；不启用 MQTT
发送时仍可生成并保存数据，程序重新启动后可接续序号与摘要链。

- 独立测试库：4批共40条记录校验通过，序号及摘要链连续，
  并完成程序退出后重新启动的续批验证。
- 独立100设备测试：100个不同公钥，生成100批、1000条记录，
  逐批验证通过，数据已保存且 MQTT 状态均为 pending。

以上本地测试未连接 MQTT 或中心，不代表已完成真实断网补传、
100台设备30分钟稳定性测试或 P95 延迟测试。
